Fungsi/Kegunaan dari Setiap Metric:
1. compute.googleapis.com/instance/cpu/utilization (CPU Utilization):
   Memantau persentase utilisasi pemrosesan CPU pada masing-masing VM instance di managed instance group. Metrik ini krusial sebagai pemicu (trigger) autoscaling (target 80%) guna mendeteksi lonjakan beban traffic flash sale dan melakukan scale-out secara otomatis.
2. compute.googleapis.com/instance/network/received_bytes_count (Network Inbound Traffic):
   Memantau volume data masuk (incoming network traffic) dalam satuan bytes pada antarmuka jaringan VM. Berfungsi menganalisis kepadatan request pelanggan dan mendeteksi anomali lonjakan traffic atau potensi serangan DoS.
3. compute.googleapis.com/instance/disk/read_bytes_count (Disk Read Bytes):
   Memantau throughput operasi pembacaan disk storage persistent pada instance e-commerce. Berguna untuk memantau performa I/O disk saat aplikasi membaca aset statis dan file web e-commerce.
4. loadbalancing.googleapis.com/https/request_count (Load Balancer Request Count):
   Memantau total volume HTTP request yang diterima dan didistribusikan oleh Global External HTTP Load Balancer ke masing-masing backend instance group. Metrik ini memberikan visibilitas menyeluruh atas total traffic global dan pembagian beban antar region Asia dan Eropa.

Alasan Pemilihan Machine Type, Region, dan Load Balancer Type:
1. Alasan Pemilihan Machine Type (e2-micro):
   Sesuai prinsip arsitektur cloud "Cost-Effective & Elastic Architecture", beban kerja aplikasi web e-commerce statis yang ringan sangat efisien dijalankan di atas machine type e2-micro (2 vCPU burstable, 1 GB RAM). Skalabilitas beban tinggi tidak ditangani dengan memperbesar ukuran mesin (vertical scaling), melainkan dengan Managed Instance Group Autoscaling (horizontal scaling). Hal ini menekan biaya operasional harian hingga level minimal (Rp 15.000 - Rp 25.000/hari) tanpa mengorbankan performa saat traffic melonjak.
2. Alasan Pemilihan Region (asia-southeast2 & europe-west1):
